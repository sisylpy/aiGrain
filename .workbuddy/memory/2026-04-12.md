# 2026-04-12 工作日志

## 项目启动修复

### 问题描述
迁移了 GbDistributerGoodsController 后，项目无法编译和启动，有多处报错。

### 修复内容

#### 1. Maven JDK 版本问题
- **问题**：Maven 默认用 JDK 1.8，但项目需要 Java 17
- **解决**：使用 `JAVA_HOME=/usr/local/opt/openjdk@17 mvn compile`

#### 2. Service 层接口继承冲突
- **问题**：`GbDistributerFatherGoodsService` 错误继承了 `IService`，导致 `void save()` 与 `IService.save()` 的 `boolean` 返回值冲突
- **解决**：去掉继承，改为普通接口，保留所有老项目方法

#### 3. NxGoodsService 方法缺失
- **问题**：`NxGoodsService` 继承了 `IService`，但缺少 `queryObject(Integer)` 方法
- **解决**：添加 `default NxGoodsEntity queryObject(Integer)` 方法，内部委托给 `getById()`

#### 4. GbDistributerStandardService 缺失方法
- **问题**：接口只有空壳，缺少 `queryDisStandardByDisGoodsIdGb()` 等方法
- **解决**：补全接口 + Impl + Mapper + 创建 Mapper XML

#### 5. DateUtils 工具类缺失方法
- **问题**：新项目的 DateUtils 是精简版，缺少 `formatWhatYearDayTime`、`formatWhatTime`、`formatWhatDate` 等方法
- **解决**：直接用老项目完整版替换 `DateUtils.java`

#### 6. PinYin4jUtils 缺失方法
- **问题**：Controller 使用 `hanziToPinyin()` 但工具类里没有
- **解决**：用老项目完整版替换 `PinYin4jUtils.java`

#### 7. GbDepartmentOrdersService.update() 类型不兼容
- **问题**：Controller 调用 `update(Entity)` 但 IService 只有 `updateById(Entity)`
- **解决**：在接口中添加 `void update(GbDepartmentOrdersEntity)` 方法，Impl 内部调用 `updateById()`

#### 8. @MapperScan 只扫描 mapper 包
- **问题**：`@MapperScan("com.nongxinle.mapper")` 不扫描 `com.nongxinle.dao` 包，导致 `GbDistributerFatherGoodsDao` Bean 找不到
- **解决**：改为 `@MapperScan({"com.nongxinle.mapper", "com.nongxinle.dao"})`

### 最终结果
- 编译：`BUILD SUCCESS`（仅 1 个 Lombok equals/hashCode 警告，不影响）
- 启动：`Tomcat started with port 8090`，`Started AigrainApplication in 5.149 seconds`
