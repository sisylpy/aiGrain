# 项目迁移注意事项

## 1. Lombok 日志注解

### 问题
Controller 中使用 `log.info()` 但未声明 `log` 变量。

### 解决方案
在 Controller 类上添加 `@Slf4j` 注解：
```java
import lombok.extern.slf4j.Slf4j;

@RestController
@RequestMapping("xxx")
@Slf4j
public class XxxController {
    // log.info() 可直接使用
}
```

### 注意
- 确保 `pom.xml` 中有 `lombok` 依赖
- 已有 `@Data`、`@AllArgsConstructor` 等 Lombok 注解的项目通常已配置

## 2. MySQL only_full_group_by 模式兼容

### 问题
`select *` 配合 `GROUP BY` 在 MySQL 8 默认严格模式下报错：
```
Expression #16 of SELECT list is not in GROUP BY clause...
```

### 解决方案
**方式一**：明确指定 SELECT 的列（推荐）
```sql
-- 错误
SELECT * FROM table GROUP BY col1

-- 正确：只查询 GROUP BY 的列或聚合函数列
SELECT DISTINCT col1, col2 FROM table ...
```

**方式二**：修改 MySQL 配置（不推荐生产环境）
```sql
SET GLOBAL sql_mode=(SELECT REPLACE(@@sql_mode,'ONLY_FULL_GROUP_BY',''));
```

### 迁移检查清单
- [ ] 所有使用 `GROUP BY` 的 SQL 检查 SELECT 列是否在 GROUP BY 中
- [ ] 优先使用 `DISTINCT` 替代 `GROUP BY` 进行去重
- [ ] ResultMap 中 `<result>` 的 column 必须与 SQL 中实际列名一致

## 3. 数据库列名与 Entity 映射

### 问题
Entity 字段名与数据库实际列名不一致导致 `Unknown column` 错误。

### 常见错误示例
```java
// Entity 中定义的字段（错误）
private String gbDuUserName;  // 对应数据库 gb_DU_user_name ❌

// 正确：根据数据库实际列名（MyBatis-Plus 自动转换下划线→驼峰）
private String gbDuWxNickName;  // 对应 gb_du_wx_nick_name ✓
```

### MyBatis-Plus 映射规则
- 数据库：`gb_du_wx_nick_name` → Java：`gbDuWxNickName`
- 使用 `@TableField("gb_du_wx_nick_name")` 可显式指定列名

### 迁移检查清单
- [ ] 首次使用新表前，通过数据库连接工具确认实际列名
- [ ] 对照 Entity 字段与数据库列名，确保命名一致
- [ ] XML 中的 `<result property="xxx" column="yyy"/>` column 必须与 SQL 中的列名完全一致（包括大小写）

## 4. 状态查询条件方向

### 问题
查询"已完成"状态的订单，使用 `status < 4` 逻辑错误。

### 正确理解
```java
// 查询已完成（状态 > 4）
map.put("dayuStatus", 4);  // XML: gb_DPG_status > #{dayuStatus}

// 查询未完成（状态 <= 4）
map.put("status", 4);      // XML: gb_DPG_status <= #{status}
```

### 迁移检查清单
- [ ] 确认业务状态值的大小关系
- [ ] 确认 XML 中的比较运算符（`<` / `>` / `=`）与业务逻辑匹配

---

## 5. 快速验证方法

迁移后用以下 SQL 快速检查 Entity 映射：

```sql
-- 检查 Entity 字段对应的数据库列是否存在
DESCRIBE gb_department_user;

-- 检查 Entity 中使用的列名是否正确
SHOW COLUMNS FROM gb_department_user LIKE '%user%';
```

## 6. 建议的迁移流程

1. **数据库层**
   - [ ] 确认数据库连接正常
   - [ ] 检查目标表的实际列名

2. **Entity 层**
   - [ ] 确认 Entity 字段与数据库列名匹配
   - [ ] 检查 `@TableName`、`@TableId` 注解

3. **XML/Mapper 层**
   - [ ] 检查 ResultMap 列名映射
   - [ ] 检查 SQL 中 SELECT 的列名
   - [ ] GROUP BY / DISTINCT 使用正确

4. **Service/Controller 层**
   - [ ] 检查 `@Slf4j` 注解
   - [ ] 确认参数名与 XML 中 `#{param}` 一致

5. **编译测试**
   - [ ] `mvn compile` 无报错
   - [ ] 启动应用测试接口
