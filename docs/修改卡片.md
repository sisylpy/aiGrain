> **协议更新（2026-05）**：正式出口为 Run / 消息上的 **`cards[]`**（`cardType` + `payload` + `source`）。根级 **`cardPayload`** 为 deprecated 兼容（`data` 镜像 `cards[0].payload`），**勿再扩展**。菜单顾问 P1 卡片清单见 **`docs/ai/menu-operation-p1-card-summary.md`**；前端契约见 **`docs/api/frontend-api-contract.md` §7.14–§7.15**。

新增/改造一个 AI 业务卡片能力，不要只改后端 Tool，也不要只改前端。

必须按完整 Harness 卡片链路实现：

1. 语义合同层
- 明确 selectedContractId
- 明确 wire
- 明确 selectedTools
- 不写 rawMessage contains
- 不新增 alias / fallback
- 不改不相关合同s

2. Tool / Adapter 层
- 复用已有小程序 Service / 业务 Service / Mapper，不要新建重复 SQL
- Tool 返回结构化 data
- 如果适合，Tool envelope.data.cardPayload 可直接带卡片
- 不要在 Tool 里拼最终自然语言

3. AnswerPlan 层
- 如果该业务已有 AnswerPlan，卡片应优先从 AnswerPlan 投影
- 新增 XxxAnswerPlanCardSupport
- 从 AnswerPlan 的定稿字段生成 cardPayload
- Tool cardPayload 有效时不覆盖；Tool 没有时 AnswerPlan 兜底

4. RunState / CardPayload 出口
   必须确认：
- AiRunState.cardPayload
- AiRunState.cards
- AiCardPayloadWireSupport.refreshAllCardPayloads
- answer_delta.data.cardPayload / cards
- run_finished.data.cardPayload / cards
- GET /ai/runs/{runId} 根级 cardPayload / cards
- 历史 message.cardPayload / cards，如当前机制支持

5. 前端小程序
   必须同步告诉前端：
- cardType 名称
- cardPayload.data 字段
- pages/storeAiChat/storeAiChat 是否识别该 cardType
- 组件只展示后端数据，不请求新接口，不做业务计算

6. 验收
   必须给出：
- 测试问句
- expected selectedContractId
- expected usedToolId
- expected AnswerPlan type
- expected cardType
- GET /ai/runs 根级 cardPayload 是否存在
- 小程序页面是否显示卡片



最推荐的实现方式

以后统一用这个模式：

1. Tool 返回业务 data
2. AnswerPlan 负责定稿事实
3. XxxAnswerPlanCardSupport 负责把 AnswerPlan 投影为 **cards[]** 条目
4. AiCardPayloadWireSupport 统一提升到 AiRunState（`cards[]` 为主，`cardPayload` 仅兼容）
5. AiRunService / AiRunController 统一输出 root **cards[]**（及 deprecated cardPayload）
6. 小程序 storeAiChat 根据 cardType 渲染组件

成本卡片可以作为 Tool envelope cardPayload 成功参考。
销售卡片可以作为 AnswerPlan 兜底投影成功参考。

以后更推荐以销售卡片这种方式为主，因为它更符合你的架构：

AnswerPlan 是事实出口；
CardPayload 是 AnswerPlan 的展示出口；
Composer 只是文字出口。
给 Cursor 的一句总原则

以后每次加卡片，都先发这句：

不要只实现卡片生成，要实现完整卡片链路：Tool/AnswerPlan → CardPayload → AiRunState → SSE/GET/message → 小程序组件。参考成本卡片的 Tool envelope 成功链路，以及销售卡片的 AnswerPlan 兜底投影链路。禁止只把 cardPayload 放在 harnessDebug，正式根级必须输出 cardPayload/cards。

这条你可以保存下来，以后每个业务卡片都按这个模板走
