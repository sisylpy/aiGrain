# 数据字段词典（AI 主对话）

本文件是 **餐厅经营数据口径的单一说明源**：下文【餐厅真实数据】里出现的是**本月实例数字**，**名词、字段含义、能否混用**一律以本词典为准。若某注入块为空的说明文字与实例冲突，以**实例块文字 + 本词典**判定，不得臆造未注入的数字。

---

## 1. 采购商品行表 `gb_distributer_purchase_goods`

每笔 **采购 / 入库完成的商品行**（一条记录 = 某次入库里的一项原料或商品）。

| 字段（含常见别名写法） | 含义 |
|------------------------|------|
| `gb_DPG_dis_goods_id` | 批发商侧分销商品 ID（配料/原料在本系统的商品维度）。 |
| `gb_dg_goods_standardname` | **主档计价单位/规格名**（在 **`gb_distributer_goods`** 上，经 `gb_DPG_dis_goods_id` 关联）。展示「¥单价/袋、/斤」等时 **优先**用主档此字段；**不是**采购行上的 `gb_DPG_standard`（本行规格可能与之相同或不同，以主档为准）。 |
| `gb_DPG_buy_subtotal` | **金额小计**：本条入库行的采购金额（数量×单价等汇总后的**行金额**，常几十～几百元）。**不是**「单价」。 |
| `gb_DPG_buy_price` | **入库单价**：单位价格，单位与主档 **`gb_dg_goods_standardname`** 对齐（缺省时再参考本行 `gb_DPG_standard`）。**回答「单价、进价、最贵/最便宜、最高/最低单价」时必须使用该字段**，不得用 `gb_DPG_buy_subtotal`。 |
| `gb_DPG_buy_quantity` | 入库数量（与规格单位配合理解）。 |
| `gb_DPG_standard` | 规格单位（如斤、袋、桶）。 |
| `gb_DPG_purchase_type` | 采购行类型，见下节。 |
| `gb_DPG_purchase_nx_supplier_id` | **供货渠道**：`-1` = 自采通道；**正整数** = 供货商（nx）ID。**同一 `type=1` 行也可能 nx 为正**，表示供货商供货入库，不能仅凭 type=1 统称「全是自采」。 |
| `gb_DPG_stock_finish_date` | **入库完成日**（字符串日期）。AI 侧「本月采购」按月筛选时优先用此字段（与前台采购统计常见口径一致）。 |
| `gb_DPG_status` | 行状态；事实查询通常要求 **`> 2`** 表示已进入可统计的完成态（具体业务以接口约定为准）。 |
| `gb_DPG_distributer_id` | 批发商 ID。 |
| `gb_DPG_purchase_department_id` | **采购部门 ID**。单店会话可能按「门店展开部门」收窄；若库中为 **NULL**，在 `IN (部门列表)` 条件下**匹配不到**，会出现「库中有单、注入块行数为 0」——属数据未落部门或口径不一致，不是说表里没有采购。 |
| `gb_DPG_purchase_type = 9` | **退货**等；全量采购统计常 **排除** 此类行。 |

---

## 2. `gb_DPG_purchase_type`（采购类型）

与 **采购批次订货方式**（手动/自动）不是同一套枚举。

| 库值 | 常量含义（文案） |
|------|------------------|
| `1` | **自采**（`SELF_PURCHASE`）。业务上仍须对照 **`gb_DPG_purchase_nx_supplier_id`**：正整数表示供货商维度供货。 |
| `5` | **向供货商 / 配送商订货**（`DELIVERY_SUPPLIER`）。【本月供货商订货采购】注入块 **仅统计 type=5**。 |
| `9` | **退货**（`RETURN`）等；一般从采购金额结构中排除。 |

**易错点**：业务若把「配送商送货」记在 **type=1 且 nx 为正**，则【本月供货商订货采购】的 type=5 行数可能为 0，**但仍有供货商维度**——须看供货摘要与 nx，不得说「完全没有供货商配送」。

---

## 3. 两套「金额 / 单价」：绝对不混用

- **`gb_DPG_buy_subtotal`**：**行金额 / 小计**。用于「本月采购花了多少钱、按商品金额 Top、订货金额合计」等。
- **`gb_DPG_buy_price`**：**入库单价**。用于「单价波动、单价最高/最低、进价对比」等。

**禁止**：把 Top 金额、金额摘录、合计里的「¥」当成某一商品的**单价**；也禁止把【本月供货商订货采购】里 **按小计排序**的「¥」叙述成「××元/单位」的单价——除非同一句明确引用 **`gb_DPG_buy_price`**。

---

## 4. 库存扣减 / 出库成本 vs 采购

- **库存减少 / 生产成本分摊**等：来自 **`gb_department_goods_stock_reduce`** 等出库流水；**`gb_dgsr_type`** 与 **`GbConstants.StockReduceType`** 一致：`1`=生产/成本，`2`**=废弃（WASTE）**，`3`**=损失成本（LOSS）**，`4`=退货——**勿**将 2 与 3 的语义对调。与 **采购表** 不是同一口径。
- **禁止**：把「本月库存减少」里 type=1 **出库成本**说成 **本月采购额**，或与 `gb_DPG_buy_subtotal` **混加、混对比**。

### 4.1 出库结构三类比率（损耗率 / 废弃率 / 制作率）

以下比率**只使用库存扣减表** `gb_department_goods_stock_reduce` 的 **`gb_dgsr_subtotal`（金额）**，**不按重量**；与 **`GbConstants.StockReduceType`** 一致。

**统一分母（系统内默认的「损耗率 / 废弃率 / 制作率」）**：

- 同一统计区间、同一统计范围（部门 scope）内，对**单品或全店**：分母 = **type=1 + type=2 + type=3** 的金额合计（**不含** type=4 退货）。
- 先按维度（如 `gb_dgsr_gb_dis_goods_id`）把各 type 金额加总，再算比率，**禁止**用「全店分母 + 单品分子」混算。

| 名称（对用户可说） | 计算 | 代码 / 报表对齐 |
|--------------------|------|------------------|
| **损耗率**（出库结构） | **(type2 + type3) ÷ (type1+type2+type3)** | 与 `GbConstants` 注释「**区间损耗率**」一致；全店区间维度与报表 `scopeOutboundSubtotals` 中 `wasteLossAmountType23` / `subtotalOutbound123` 同源（2+3 为分子、1+2+3 为分母）。 |
| **废弃率**（出库结构） | **type2 ÷ (type1+type2+type3)** | type2 = 废弃（WASTE）。 |
| **制作率**（亦称 **生产出库占比**、口语可称 **出库率**） | **type1 ÷ (type1+type2+type3)** | type1 = 生产/成本（PRODUCTION）；三者占分母比例之和为 100%。 |

**用户说「损耗率」但未指定分母时**：模型**优先**采用上表 **出库结构损耗率**（相对 1+2+3），并**一句话说明**「相对本月生产+废弃+损失出库金额」；**不要**默认改用采购作分母。

**若要用采购作分母**（须单独命名，**不得**简称「损耗率」而不说明）：

- **损耗占采购比**：**(type2 + type3) ÷** 同品、同月 **`gb_distributer_purchase_goods.gb_DPG_buy_subtotal`** 合计（采购口径，与出库表**不同源**，不得与上表三率混在同一句话的分母里）。

### 4.2 配料行与 `depGetAllFood`：利用率、用量偏差、成本偏差

与 **`POST /gbdepfood/depGetAllFood`**（四参齐）、**`/gbDishCostAnalysis/ingredientAnalysis`**、配方行 **`ingredientAnalysisRows`** 等同源。本节与 **§4.1** 不同：§4.1 是**出库金额**在 type1/2/3 之间的**结构占比**；本节是 **「理论用量/成本」vs「实际生产或整单出库」** 的对比——**不得**把 §4.1 的 **「制作率 / 出库率」**（type1÷(1+2+3) 金额）说成配料行的 **「利用率」**。

#### 配料行（按料，重量类字段）

| 名称（对用户可说） | 含义 | 与字段对齐 |
|--------------------|------|------------|
| **利用率** | 仅 **生产出库 type=1** 摊到本菜本料的用量 ÷ **配方理论用量** | 配料行 **`utilizationRate`**：分子为 **`actualProduceUsage`**（alloc1，**不含** type2/3）；分母 **`theoryUsage`**。与 `bossColumnHintsZh` / 配料分析说明一致。 |
| **用量偏差率**（亦称 **实际相对理论超耗率**） | **含报损报失的全量出库用量**相对理论的偏离 | 分子/分母用 **`actualUsage`**（type **1+2+3** 摊到本菜本料重量合计）与 **`theoryUsage`**。示例：**偏差率** = (actualUsage − theoryUsage) ÷ theoryUsage；口语也可用 **「实际用量是理论的多少倍」** = actualUsage ÷ theoryUsage。**禁止**把该比称为「利用率」——会与上表 **`utilizationRate`** 冲突。 |

#### 整菜（`gbDfBusinessInsight` 等，金额）

| 名称（对用户可说） | 含义 | 与字段对齐 |
|--------------------|------|------------|
| **生产侧成本偏差率** | **仅 type=1 生产**分摊的实际成本相对理论成本的偏离 | **`actualCostAmount`**（仅 type1，与 `report.salesDishRows` 同源）相对 **`theoryCostAmount`**。示例：(actualCostAmount − theoryCostAmount) ÷ theoryCostAmount（无理论成本或分母为 0 时不强算百分比，改口述差额）。 |
| **整单实际成本相对理论的偏差** | **含 type1+2+3 摊销**的整菜区间实际成本相对理论成本的偏离 | **`actualCostTotalAmount123`**（`actualCostPerPortion123 ×` 销量）相对 **`theoryCostAmount`**。与「生产侧成本偏差」**不要**用同一句混成同一个名字——前者包含损耗/损失摊入整单。 |

**模型叙述边界**：对用户尽量说「生产用料利用率」「相对理论多用了几成」「整单含报损后的成本比理论高多少」，避免在同一段里交替使用「出库率」（§4.1）与「利用率」（本节）却不说明分母差异。

## 5. 订货 / 到货节奏：`gb_department_orders`

- 与 **采购入库表** 不同：侧重 **部门订货订单、到货日**（如 `gb_DO_arrive_date`）。
- **采购/进货/订货频率、节奏好不好**：若注入了【订货/到货频率与习惯】，**优先引用该块**；不要用【本月采购数据】的入库笔数 **顶替**「订货频率」结论。

---

## 6. 供货商未结账（批次维度）

- 常见注入标题：【供货商未结账款（采购批次）】。
- 口径：**采购批次**表（如 `gb_distributer_purchase_batch`）未结账状态（如 `status=3`）对应金额，**不是**单笔采购商品行的简单加总。不得与「单笔采购小计」混谈。

## 7. 门店画像字段（仅「数据提取 JSON」用）

用户口头提到要入库的经营数字时，须使用系统约定字段名（示例）：

| 字段名 | 含义 |
|--------|------|
| `gb_ai_restaurant_profile_daily_revenue` | 日均营收 |
| `gb_ai_restaurant_profile_rent_monthly` | 月租金 |
| `gb_ai_restaurant_profile_monthly_wage` | 月工资预算 |
| `gb_ai_restaurant_profile_monthly_fixed_cost` | **其它月固定成本**（水电物业等合计口径，不含人工时按产品定义） |

## 8. 注入块标题与用途速查

| 块标题（可能出现在【餐厅真实数据】中） | 主要数据来源 | 典型用途 |
|----------------------------------------|--------------|----------|
| 【本月采购数据】 | `gb_distributer_purchase_goods`（多类型，常排除退货） | 采购金额结构、供货摘要、摘录 |
| 【本月供货商订货采购】 | 同上表，**仅 type=5** | 「给供货商订了哪些」、配送商订货金额结构（注意小计 vs 单价） |
| 【本月自采金额（采购商品行）】 | 同上表，**自采口径**采购行 | 自采金额 Top、**自采入库单价 Top**（`gb_DPG_buy_price`，单位优先主档 **`gb_dg_goods_standardname`**）；**口语勿念** `type=1` |
| 【本月采购入库单价摘录】 | 同上表，**gb_DPG_buy_price** | 「单价最小/最大」等极值 |
| 【本月采购单价波动（采购商品行）】 | 同源统计 + 入库单价 | 同品多笔 **价差**；须逐字引用表内 **buy_price** |
| 【订货/到货频率与习惯】 | `gb_department_orders` 等 | 到货节奏、订货习惯 |
| 【本月库存减少数据】 | 库存扣减流水 | 出库成本、损耗等，**非**采购额 |
| **部门菜品列表（经营分析四参齐）** | `POST /gbdepfood/depGetAllFood` → `gbDfBusinessInsight`、`ingredientAnalysisRows`、配方行出库统计 | 理论/实际成本、**利用率**与 **用量偏差**、毛利率等；名词与 **§4.2** 对齐 |
| 【供货商未结账款（采购批次）】 | 采购批次 | 应付 / 未结净额 |

## 9. 表述边界（与系统规则一致）

- **对用户**：盘点库存减少、采购 Top、波动榜等时，只称**商品名称**（注入中已解析）；**勿**单独说「商品 ID=6」类表述。
- **对老板口语**：说明配送/自采时尽量用「配送商订货」「供货商送货」「自采」；**不必**复述 `type=5`、`type=1` 等内部枚举数字。
- **禁止**在没有满足「type=5、type=1 且 nx 为正、摘录 nx」全为无供货商证据时，使用「100% 自采」「完全没有供货商配送」等**绝对化**结论。
- **禁止**在【本月采购数据】标明「金额摘录已省略」时，**编造**采购金额明细或排名。
- 仅有 **供货商 ID**、无名称映射时：只能谈 **ID 与金额结构**，不得编造供应商公司名。

## 10. 修订说明（给人看）

运维或产品改口径时：**优先改本文件 + 服务端 SQL/注入文案**，再视需要变薄 `ai-skill-procurement-structure.md` 等 Skill 中的重复段落，避免三处四种说法。
